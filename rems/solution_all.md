## 🎯 ЧТО МЫ ДЕЛАЕМ?

У нас есть массив чисел. Мы проходим по нему **слева направо** и на каждом шаге:
1. Смотрим, какой у числа остаток
2. Считаем, сколько **уже было** чисел с таким же остатком
3. Добавляем это число к ответу (потому что текущее число образует пару с каждым из них)
4. Запоминаем, что теперь чисел с таким остатком стало на 1 больше

---

## 📚 АНАЛОГИЯ (ЧТОБЫ БЫЛО ПОНЯТНО)

Представьте, что вы **собираете коллекцию марок**. У вас есть **200 коробок**, подписанных числами от 0 до 199.

**Правило:** Марки с одинаковым остатком кладутся в одну коробку.

**Процесс:**
1. Берёте новую марку
2. Смотрите, какой у неё остаток (например, 3)
3. Идёте к коробке №3
4. Смотрите, сколько там уже марок (например, 2)
5. **Каждая из этих 2 марок образует пару с новой** → добавляете 2 к ответу
6. Кладёте новую марку в коробку №3 (теперь там 3 марки)

## 🎯 ПОЧЕМУ `ans += count[rem]` А НЕ `ans++`?

### Если бы мы писали `ans++`:

```cpp
// НЕПРАВИЛЬНО!
if (count[rem] > 0) {
    ans++;  // добавили бы только 1
}
```

**Проблема:** Если в коробке уже 3 числа, новое число образует пару с **каждым** из них, а не только с одним!

### Пример:
```
В коробке уже 3 числа: [A, B, C]
Приходит новое число: D

Пары: (A,D), (B,D), (C,D) → 3 новые пары!

Правильно: ans += 3 (count[rem] = 3)
Неправильно: ans++ (добавили бы только 1)
```

### Пример с 4 числами одного остатка:

```
Шаг 1: [1]              count=1  ans=0
Шаг 2: [1, 2]           count=2  ans += 1 → ans=1  (пара: 1-2)
Шаг 3: [1, 2, 3]        count=3  ans += 2 → ans=3  (пары: 1-3, 2-3)
Шаг 4: [1, 2, 3, 4]     count=4  ans += 3 → ans=6  (пары: 1-4, 2-4, 3-4)
```

**Итог:** 6 пар = C(4, 2) ✅

```
На каждой итерации:

2. Количество таких чисел = count[rem]
```

# 🎯 РАЗБОР ЗАДАЧИ: ПАРЫ С ОДИНАКОВЫМ ОСТАТКОМ

## 📖 УСЛОВИЕ (ПРОСТЫМИ СЛОВАМИ)

Дан массив чисел. Нужно найти количество пар `(i, j)`, где `i < j`, таких что:

```
|ai - aj| % 200 == 0
```

**Что это значит:** Разность чисел **делится на 200 без остатка**.

**Другими словами:** У чисел **одинаковый остаток при делении на 200**.

---

## 🧠 КЛЮЧЕВАЯ ИДЕЯ

### Почему `|ai - aj| % 200 == 0` означает одинаковый остаток?

**Правило:**
```
Если два числа дают одинаковый остаток при делении на 200,
то их разность делится на 200.
```

**Пример:**
```
203 % 200 = 3
403 % 200 = 3
Остатки одинаковые → |203 - 403| = 200 → 200 % 200 = 0 ✅
```

```
203 % 200 = 3
404 % 200 = 4
Остатки разные → |203 - 404| = 201 → 201 % 200 = 1 ❌
```

## 💻 РЕШЕНИЕ НА C++

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    cin >> n;
    
    // Массив для подсчёта остатков (0..199)
    vector<long long> count(200, 0);
    
    // Читаем числа и считаем остатки
    for (int i = 0; i < n; ++i) {
        long long x;
        cin >> x;
        int rem = x % 200;  // остаток от деления на 200
        count[rem]++;       // увеличиваем счётчик для этого остатка
    }
    
    // Считаем количество пар
    long long answer = 0;
    for (int r = 0; r < 200; ++r) {
        long long cnt = count[r];
        if (cnt >= 2) {
            // Число пар = C(cnt, 2) = cnt * (cnt - 1) / 2
            answer += cnt * (cnt - 1) / 2;
        }
    }
    
    cout << answer << endl;
    return 0;
}
```

## 🧮 ПОЧЕМУ ФОРМУЛА `cnt * (cnt - 1) / 2`?

**Формула числа сочетаний:** количество способов выбрать 2 элемента из `cnt`.

```
C(cnt, 2) = cnt * (cnt - 1) / 2
```

**Пример:** Если `cnt = 4`:
```
Пары: (1,2), (1,3), (1,4), (2,3), (2,4), (3,4)
Всего: 6 пар
4 * 3 / 2 = 6 ✅
```

## ⚠️ ВАЖНОЕ ЗАМЕЧАНИЕ

**Почему массив размером 200?**

Потому что остатки от деления на 200 могут быть только от 0 до 199. Всего 200 вариантов.

```cpp
vector<long long> count(200, 0);  // индексы 0..199
```

**Почему `long long`?**

- `n` может быть до 200 000
- Максимальное количество пар: 200 000 * 199 999 / 2 ≈ 2 × 10¹⁰
- Это число не помещается в `int` (2³¹ ≈ 2.1 × 10⁹)
- Нужно использовать `long long`

---

## 📝 КОРОТКАЯ ВЕРСИЯ

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    cin >> n;
    
    vector<long long> cnt(200, 0);
    for (int i = 0; i < n; ++i) {
        long long x;
        cin >> x;
        cnt[x % 200]++;
    }
    
    long long ans = 0;
    for (int i = 0; i < 200; ++i) {
        ans += cnt[i] * (cnt[i] - 1) / 2;
    }
    
    cout << ans << endl;
    return 0;
}
```

## 🎯 ПОЧЕМУ ЭТО РАБОТАЕТ? (ОБЪЯСНЕНИЕ)

### Математическое доказательство:

**Утверждение:** `|a - b| % 200 == 0` ⇔ `a % 200 == b % 200`

**Доказательство:**
1. **Если остатки равны:**  
   `a = 200*k1 + r`, `b = 200*k2 + r`  
   `|a - b| = |200*k1 - 200*k2| = 200 * |k1 - k2|`  
   → делится на 200 без остатка ✅

2. **Если разность делится на 200:**  
   `|a - b| = 200 * t`  
   → `a % 200 == b % 200` (оба дают одинаковый остаток) ✅

**Значит, нам нужно просто сгруппировать числа по остаткам!**

## 🔥 ЧАСТЫЕ ОШИБКИ

| Ошибка | Почему неправильно | Как исправить |
|--------|-------------------|---------------|
| **Использую `int` для ответа** | Ответ может быть > 2³¹ | Использовать `long long` |
| **Ищу пары через вложенные циклы** | O(n²) → Time Limit | Использовать формулу C(n,2) |
| **Забываю про остаток 0** | `x % 200 == 0` — тоже остаток | Считать его как остаток 0 |
| **Не использую `% 200`** | Остаток может быть больше 199 | Обязательно брать `% 200` |

---

## 🎓 ИТОГ

**Ключевые идеи:**

1. **Свойство:** `|a-b| % 200 == 0` ⇔ `a % 200 == b % 200`
2. **Подход:** Группируем числа по остаткам
3. **Формула:** Для каждой группы из `cnt` элементов → `cnt*(cnt-1)/2` пар
4. **Сложность:** O(n) времени, O(1) памяти

**Это решение проходит все тесты!** 🚀

# 📊 СЛОЖНОСТЬ O(n) ВРЕМЕНИ И O(1) ПАМЯТИ — ПОДРОБНОЕ ОБЪЯСНЕНИЕ

Давайте разберём **каждую букву** в этой формуле, чтобы вы могли уверенно объяснять это на собеседовании.

---

## ЧАСТЬ 1: ЧТО ТАКОЕ O(n) ПО ВРЕМЕНИ?

### Буквально:

**O(n)** означает, что время работы алгоритма **растёт линейно** с ростом размера входных данных.

**Простыми словами:**
- Если у вас **n = 10** элементов → алгоритм делает ~10 операций
- Если **n = 100** → делает ~100 операций
- Если **n = 100 000** → делает ~100 000 операций

**То есть:** время работы = `константа × n`

---

### Почему наша задача — O(n)?

```cpp
int n;
cin >> n;  // O(1) — константа

vector<long long> count(200, 0);  // O(1) — константа

// ЭТОТ ЦИКЛ — O(n) — ГЛАВНАЯ ЧАСТЬ!
for (int i = 0; i < n; ++i) {      // ← выполняется n раз
    long long x;
    cin >> x;                       // O(1) на каждую итерацию
    int rem = x % 200;              // O(1) на каждую итерацию
    count[rem]++;                   // O(1) на каждую итерацию
}

// ЭТОТ ЦИКЛ — O(200) = O(1) — КОНСТАНТА!
for (int r = 0; r < 200; ++r) {    // ← выполняется всегда 200 раз
    ans += count[r] * (count[r] - 1) / 2;  // O(1)
}
```

**Подсчёт операций:**

| Часть кода | Сколько раз выполняется | Сложность |
|------------|-------------------------|-----------|
| Чтение n | 1 раз | O(1) |
| Создание массива | 1 раз | O(1) |
| **Цикл чтения чисел** | **n раз** | **O(n)** |
| Цикл подсчёта пар | 200 раз | O(200) = O(1) |

**Итог:** O(n) + O(1) + O(1) = **O(n)**

---

### Визуализация O(n)

```
Время работы
    ↑
    |                                    O(n²)
    |                                 /
    |                              /
    |                           /
    |                        /
    |                     /
    |                  /
    |               /
    |            /  ← O(n) — прямая линия
    |         /
    |      /
    |   /
    |/
    +-----------------------------------------→ n (размер данных)
```

**График O(n)** — это прямая линия. Если данных в 2 раза больше — время в 2 раза больше.

---

### Почему здесь n, а не что-то ещё?

**n** — это количество элементов в массиве (входных данных).

В нашей задаче:
- `n` может быть от 1 до 200 000
- Алгоритм делает **один проход** по массиву
- Значит, он делает **n операций** чтения/обработки

**Если бы было два вложенных цикла:**
```cpp
for (int i = 0; i < n; ++i) {
    for (int j = 0; j < n; ++j) {  // ← вложенный цикл
        // делаем что-то
    }
}
```
Это было бы O(n²) — время растёт квадратично.

## ЧАСТЬ 2: ЧТО ТАКОЕ O(1) ПО ПАМЯТИ?

### Буквально:

**O(1)** означает, что алгоритм использует **константное количество памяти**, независимо от размера входных данных.

**Простыми словами:**
- Если у вас **n = 10** → алгоритм использует ~200 ячеек памяти
- Если **n = 100** → алгоритм использует ~200 ячеек памяти
- Если **n = 100 000** → алгоритм использует ~200 ячеек памяти

**То есть:** память **не растёт** с ростом n!

---

### Почему наша задача — O(1)?

```cpp
vector<long long> count(200, 0);  // ← ВСЯ ДОПОЛНИТЕЛЬНАЯ ПАМЯТЬ!
```

**Что здесь происходит:**
- Мы создаём массив **ровно из 200 элементов**
- **Неважно**, сколько чисел в массиве: 10, 1000 или 200 000
- Массив `count` **всегда** будет занимать 200 × 8 байт ≈ 1.6 КБ

**Сравнение:**

| Размер входных данных (n) | Дополнительная память | Что храним |
|---------------------------|----------------------|------------|
| n = 10 | ~1.6 КБ | Массив на 200 элементов |
| n = 1000 | ~1.6 КБ | Массив на 200 элементов |
| n = 200 000 | ~1.6 КБ | Массив на 200 элементов |

**Память не растёт!** → O(1)

---

### Визуализация O(1) памяти

```
Используемая память
    ↑
    |                              O(n) — растёт
    |                           /
    |                        /
    |                     /
    |                  /
    |               /
    |            /
    |         /
    |      /
    |   /
    |/  ← O(1) — константа (горизонтальная линия)
    +-----------------------------------------→ n (размер данных)
```

**График O(1)** — это горизонтальная линия. Сколько бы данных ни было, память не меняется.

## 📊 СРАВНЕНИЕ РАЗНЫХ СЛОЖНОСТЕЙ

### Время (Time Complexity)

| Сложность | Время для n=10 | Время для n=1000 | Время для n=1 000 000 |
|-----------|---------------|-----------------|----------------------|
| **O(1)** | 1 операция | 1 операция | 1 операция |
| **O(log n)** | ~3 операции | ~10 операций | ~20 операций |
| **O(n)** | 10 операций | 1000 операций | 1 000 000 операций |
| **O(n²)** | 100 операций | 1 000 000 операций | 1 000 000 000 000 операций |
| **O(2ⁿ)** | 1024 операции | 2¹⁰⁰⁰ (огромно!) | невозможно |

### Память (Space Complexity)

| Сложность | Память для n=10 | Память для n=1000 | Память для n=1 000 000 |
|-----------|-----------------|-------------------|------------------------|
| **O(1)** | 1 КБ | 1 КБ | 1 КБ |
| **O(n)** | 10 КБ | 1000 КБ | 1 000 000 КБ (~1 ГБ) |
| **O(n²)** | 100 КБ | 1 000 000 КБ (~1 ГБ) | 1 000 000 000 000 КБ (~1 ПБ) |

### Ограничения задачи:


**Если бы мы хранили все числа:**

```cpp
vector<long long> arr(n);  // O(n) памяти

```
Память: 200 000 × 8 байт = **1.6 МБ** (тоже немного, но больше)

**Но мы храним только остатки:**
```cpp
vector<long long> count(200, 0);  // O(1) памяти

    long long x;
    cin >> x;
    count[x % 200]++;
}
```
Память: 200 × 8 байт = **1.6 КБ** (в 1000 раз меньше!)

## СПОСОБ 1: ПОЛНЫЙ ПЕРЕБОР (САМЫЙ ПРОСТОЙ)

### Идея
Проверяем **все возможные пары** `(i, j)`, где `i < j`.

### Блок-схема
```mermaid
flowchart TD
    A[Начало] --> B[i = 0]
    B --> C{i < n?}
    C -->|Да| D[j = i+1]
    D --> E{j < n?}
    E -->|Да| F[|arr[i]-arr[j]| % 200 == 0?]
    F -->|Да| G[ans++]
    G --> H[j++]
    H --> E
    E -->|Нет| I[i++]
    I --> C
    C -->|Нет| J[Выводим ans]
```

### Код C++
```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> arr(n);
    for (int i = 0; i < n; ++i) cin >> arr[i];
    
    long long ans = 0;
    for (int i = 0; i < n; ++i) {
        for (int j = i + 1; j < n; ++j) {
            if (abs(arr[i] - arr[j]) % 200 == 0) {
                ans++;
            }
        }
    }
    
    cout << ans << endl;
    return 0;
}
```

### Python
```python
n = int(input())
arr = list(map(int, input().split()))

ans = 0
for i in range(n):
    for j in range(i + 1, n):
        if abs(arr[i] - arr[j]) % 200 == 0:
            ans += 1

print(ans)
```

**Сложность:** O(n²) по времени, O(1) по памяти.

**Почему плохо:** При n = 200 000 → 40 000 000 000 операций → **Time Limit!**

## СПОСОБ 2: СОРТИРОВКА (ПРОСТОЙ, НО НЕ ОПТИМАЛЬНЫЙ)

### Идея
1. Сортируем массив
2. Группируем числа по остаткам

### Код C++
```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main() {
    int n;
    cin >> n;
    vector<long long> arr(n);
    for (int i = 0; i < n; ++i) cin >> arr[i];
    
    // Сортируем по остатку от деления на 200
    sort(arr.begin(), arr.end(), [](long long a, long long b) {
        return a % 200 < b % 200;
    });
    
    long long ans = 0;
    long long count = 1;
    for (int i = 1; i < n; ++i) {
        if (arr[i] % 200 == arr[i-1] % 200) {
            count++;
        } else {
            ans += count * (count - 1) / 2;
            count = 1;
        }
    }
    ans += count * (count - 1) / 2;
    
    cout << ans << endl;
    return 0;
}
```

### Python
```python
n = int(input())
arr = list(map(int, input().split()))

# Сортируем по остатку
arr.sort(key=lambda x: x % 200)

ans = 0
count = 1
for i in range(1, n):
    if arr[i] % 200 == arr[i-1] % 200:
        count += 1
    else:
        ans += count * (count - 1) // 2
        count = 1
ans += count * (count - 1) // 2

print(ans)
```

**Сложность:** O(n log n) по времени, O(1) по памяти.

**Почему не оптимально:** Можно сделать за O(n), зачем сортировать?

## СПОСОБ 3: ХЕШ-ТАБЛИЦА (УНИВЕРСАЛЬНЫЙ)

### Идея
Используем `unordered_map` для подсчёта остатков (если остатков может быть больше 200).

### Код C++
```cpp
#include <iostream>
#include <vector>
#include <unordered_map>
using namespace std;

int main() {
    int n;
    cin >> n;
    
    unordered_map<int, long long> count;
    
    for (int i = 0; i < n; ++i) {
        long long x;
        cin >> x;
        count[x % 200]++;
    }
    
    long long ans = 0;
    for (auto& [rem, cnt] : count) {
        ans += cnt * (cnt - 1) / 2;
    }
    
    cout << ans << endl;
    return 0;
}
```

### Python
```python
n = int(input())
arr = list(map(int, input().split()))

from collections import Counter
count = Counter(x % 200 for x in arr)

ans = 0
for cnt in count.values():
    ans += cnt * (cnt - 1) // 2

print(ans)
```

**Сложность:** O(n) по времени, O(n) по памяти.

**Почему не оптимально:** Память O(n) вместо O(1). Для этой задачи массив из 200 элементов лучше.

## 📚 ЧТО ТАКОЕ `unordered_map`?

**Простыми словами:** Это **волшебная коробка с ярлычками**.

Представьте, что у вас есть много коробок, и на каждой написан номер (ключ). Вы можете положить что-то в коробку по номеру и быстро найти эту коробку.

**В нашей задаче:**
- **Ключ (key)** — это остаток от деления на 200 (число от 0 до 199)
- **Значение (value)** — сколько чисел с таким остатком мы встретили

**Это самая важная строчка!** Давайте разберём по частям:

**Что делает эта строчка целиком:**
1. Находит остаток числа
2. Идёт в коробку с этим номером
3. Кладёт туда число (увеличивает счётчик на 1)

**4. `ans += ...`** — добавляем к общему ответу

## 🆚 СРАВНЕНИЕ: МАССИВ vs ХЕШ-ТАБЛИЦА

| Аспект | Массив `count[200]` | Хеш-таблица `unordered_map` |
|--------|---------------------|----------------------------|
| **Размер** | Фиксированный (200) | Динамический (только нужные) |
| **Память** | O(1) — всегда 200 ячеек | O(n) — зависит от количества ключей |
| **Скорость** | Очень быстрый (O(1)) | Чуть медленнее (O(1) сред.) |
| **Когда использовать** | Если диапазон остатков известен | Если неизвестно, сколько может быть ключей |
| **Простота** | Проще | Чуть сложнее |

2. Массив быстрее и проще
3. Память O(1) — всегда 200 ячеек

**Но `unordered_map` тоже работает!** И его можно использовать, если:
- Не знаете заранее диапазон
- Ключей может быть очень много
- Хотите более универсальное решение

## 📊 ВИЗУАЛЬНОЕ ПРЕДСТАВЛЕНИЕ

### Как выглядит `unordered_map` в памяти:

```

    0: 1,   // остаток 0 встретился 1 раз
```

### Как мы считаем пары:

```

Всего: 2 пары
```

## 🎯 КЛЮЧЕВЫЕ МОМЕНТЫ ДЛЯ ЗАПОМИНАНИЯ

1. **`unordered_map`** — это хеш-таблица (как словарь в Python)
2. **Ключи** — остатки от деления на 200 (0..199)
3. **Значения** — сколько раз встретился каждый остаток
4. **`count[x % 200]++`** — вычисляем остаток и увеличиваем счётчик
5. **`cnt * (cnt - 1) / 2`** — формула для подсчёта пар

## 📝 КАК ЭТО РАБОТАЕТ (ПРОСТОЙ ЯЗЫК)

1. **Создаём пустую коробку с ярлычками** (`unordered_map`)
2. **Для каждого числа:**
   - Смотрим, какой у него остаток
   - Идём к коробке с таким номером
   - Кладём туда число (увеличиваем счётчик)
3. **После того как все числа разложены:**
   - Берём каждую коробку
   - Считаем, сколько пар можно составить из чисел в ней
   - Складываем все пары
4. **Выводим ответ**

- ✅ Работает для любых остатков
- ✅ Универсальное решение

**Недостатки:**
- ❌ Чуть медленнее (хеширование)
- ❌ Занимает больше памяти

**В этой задаче массив лучше, но `unordered_map` тоже правильное решение!** 🚀

## СПОСОБ 4: МАССИВ ОСТАТКОВ (ОПТИМАЛЬНЫЙ) — ЭТОТ МЫ РАЗОБРАЛИ

### Идея
Используем массив фиксированного размера 200.

### Код C++ (оптимальный)
```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    
    int n;
    cin >> n;
    
    vector<long long> count(200, 0);
    
    for (int i = 0; i < n; ++i) {
        long long x;
        cin >> x;
        count[x % 200]++;
    }
    
    long long ans = 0;
    for (int r = 0; r < 200; ++r) {
        long long cnt = count[r];
        ans += cnt * (cnt - 1) / 2;
    }
    
    cout << ans << endl;
    return 0;
}
```

### Python (оптимальный)
```python
import sys

def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    
    count = [0] * 200
    for i in range(1, n + 1):
        x = int(data[i])
        count[x % 200] += 1
    
    ans = 0
    for cnt in count:
        ans += cnt * (cnt - 1) // 2
    
    print(ans)

if __name__ == "__main__":
    main()
```

**Сложность:** O(n) по времени, O(1) по памяти.

**Почему оптимально:**
- O(n) — читаем каждый элемент один раз
- O(1) — массив фиксированного размера 200
- Используем быстрый ввод/вывод

## СПОСОБ 5: ОПТИМИЗИРОВАННЫЙ ВВОД (МАКСИМАЛЬНАЯ СКОРОСТЬ)

### Идея
Используем быстрый ввод/вывод для максимальной производительности.

### Код C++ (с быстрым вводом)
```cpp
#include <iostream>
#include <vector>
using namespace std;

// Быстрый ввод целых чисел
template<typename T>
void fastRead(T& x) {
    x = 0;
    char c = getchar_unlocked();
    while (c < '0' || c > '9') c = getchar_unlocked();
    while (c >= '0' && c <= '9') {
        x = x * 10 + (c - '0');
        c = getchar_unlocked();
    }
}

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    
    int n;
    fastRead(n);
    
    vector<long long> count(200, 0);
    
    for (int i = 0; i < n; ++i) {
        long long x;
        fastRead(x);
        count[x % 200]++;
    }
    
    long long ans = 0;
    for (int r = 0; r < 200; ++r) {
        long long cnt = count[r];
        ans += cnt * (cnt - 1) / 2;
    }
    
    cout << ans << '\n';
    return 0;
}
```

### Python (с быстрым вводом)
```python
import sys

def main():
    data = sys.stdin.buffer.read().split()
    n = int(data[0])
    
    count = [0] * 200
    for i in range(1, n + 1):
        x = int(data[i])
        count[x % 200] += 1
    
    ans = sum(c * (c - 1) // 2 for c in count)
    print(ans)

if __name__ == "__main__":
    main()
```

**Сложность:** O(n) по времени, O(1) по памяти.

**Почему быстрее:** Используем буферизованный ввод, который читает все данные за один раз.

## 🚀 ЭКСТРЕМАЛЬНАЯ ОПТИМИЗАЦИЯ (ДЛЯ ГИКОВ)

### Однопроходный алгоритм с подсчётом пар на лету

```cpp
#include <iostream>
#include <vector>
using namespace std;

int main() {
    ios_base::sync_with_stdio(false);
    cin.tie(nullptr);
    
    int n;
    cin >> n;
    
    vector<long long> count(200, 0);
    long long ans = 0;
    
    for (int i = 0; i < n; ++i) {
        long long x;
        cin >> x;
        int rem = x % 200;
        
        // Добавляем все пары с этим остатком
        // (текущий элемент образует пару с каждым из уже встреченных)
        ans += count[rem];
        
        // Увеличиваем счётчик
        count[rem]++;
    }
    
    cout << ans << '\n';
    return 0;
}
```

### Почему это работает?

**Идея:** Когда мы встречаем новый элемент, он образует пару с **каждым** ранее встреченным элементом, у которого такой же остаток.

**Пример:**
```
Числа: 203, 403, 204
Остатки: 3, 3, 4

Шаг 1: 203 (rem=3) → count[3]=0 → ans=0 → count[3]=1
Шаг 2: 403 (rem=3) → count[3]=1 → ans=1 → count[3]=2
Шаг 3: 204 (rem=4) → count[4]=0 → ans=1 → count[4]=1
Итог: 1 пара (203, 403)
```

**Сложность:** O(n) по времени, O(1) по памяти.
